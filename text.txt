# 1) The complete requirements (what we’re building)

You’re building an “Intelligent Management System” that runs a **sequential agent loop** for each SKU:

Trigger underperformance → propose price & marketing actions → simulate labor impact → **evaluate & rank** → apply governance & produce a **finalized action plan**.

Per your PDF:

* Yes, the “life of an item” starts with the **TriggerAgent** and then runs pricing, marketing, and evaluation sequentially. 
* **Marketing** outputs **recommendations** (not auto-launching campaigns). 
* **Labor** is **factored into ROI**, not treated as a hard constraint. 
* **Evaluation/Finance** ranks which actions move forward **based on financial constraints**. 
* **Governance** applies guardrails dynamically; thresholds for auto vs. manual aren’t pre-set but **a governance service can be used**. 
* System is designed with **no central orchestrator** and uses a **blackboard** coordination pattern with stopping criteria (“no new SKU deltas > threshold”, “budget exhausted”). 
* Example guardrails include: **no price drops over 20%**, **skip SKUs with inventory < 10**, **labor cost ≤ $200/store/day** (you can customize these). 

Your attached CSVs line up perfectly with the PDF’s tool contracts:

* `get_sales.csv`: `sku_id, sales, forecast, plan` (15 rows)

# 2) What each agent does + data it uses

Below is aligned to both your checklist and the PDF’s environment/tooling section (get_sales, get_inventory, price_optimizer, marketing_planner, labor_simulator, launch_action). 

### TriggerAgent

* **Input**: `get_sales.csv` (actual vs forecast/plan).
* **Logic**: Find **underperformers** where `actual < forecast by X%` (default X=10–20). Also generate **choice sets** (e.g., SKU alone or grouped by similar signals).
* **Output**:

  * `flagged_skus.csv` → `sku_id, sales, forecast, plan, gap_pct, reason`
  * `choice_sets.json` → e.g. `[{ "set_id": "sku_123", "skus": ["sku_123"], "rationale": "gap=22%" }, ...]`
* **PDF tie-ins**: decisions `identify_gap`, `generate_choice_set`; algorithms “delta ranking, dynamic clustering”; tools `get_sales`. 

### PricingAgent

* **Input**: `choice_sets.json`, `price_optimizer.csv` (elasticity & optimal price).
* **Logic**: Simulate ±5–10% price changes around baseline; or adopt `optimal_price` with elasticity-based lift. (If you don’t have `current_price`, you can use `optimal_price` as “proposed” and compute expected lift via elasticity.)
* **Output**: `price_scenarios.csv` → `sku_id, proposed_price, delta_pct, expected_lift_units, notes`
* **PDF tie-ins**: “Bayesian elasticity, gradient optimization”, tool `price_optimizer`, proposals go to Product/Finance. (You can keep it deterministic for v1.) 

### MarketingAgent

* **Input**: `flagged_skus.csv`, `price_scenarios.csv`, `marketing_planner.csv` (channels, spend, lift).
* **Logic**: For each flagged SKU (and/or price scenario), pick a channel mix with expected lift, within a spend cap. Output **recommendations** (not execution).
* **Output**: `campaign_scenarios.csv` → `sku_id, channels, total_spend, expected_lift_units, notes`
* **PDF tie-ins**: “Strategize campaign actions… budget-aware bandits,” tool `marketing_planner`, **recommendations** only for demo. 

### LaborAgent

* **Input**: `labor_simulator.csv`, optionally expected lift (from pricing/marketing).
* **Logic**: Estimate incremental **labor_hours** and **cost** given expected volume lift. If you want it simple, read the per-SKU baseline from CSV; for scenario-aware estimates, scale hours by expected incremental units.
* **Output**: `labor_cost_estimates.csv` → `sku_id, labor_hours, cost, notes`
* **PDF tie-ins**: “Quantify feasibility/cost… movement simulation,” tool `labor_simulator`. **Labor is a factor in ROI, not a hard constraint.** 

### FinanceAgent

* **Input**: pricing, marketing, labor outputs; (optionally) product feedback.
* **Logic**: Compute a **simple ROI** per SKU scenario. Example:
  `IncrementalRevenue ≈ (expected_lift_units) * (assumed_unit_price)`
  `NetROI ≈ IncrementalRevenue − MarketingSpend − LaborCost`
  (If you lack price, either use `optimal_price`, a global default, or prompt UI for a “baseline price” CSV.)
* **Output**: `ranked_action_plan.csv` → `sku_id, scenario_id, roi, rank, rationale`
* **PDF tie-ins**: “mini-P&L, scenario ranking,” proposes to Governance; ranked based on **financial constraints**. 

### GovernanceAgent

* **Input**: `ranked_action_plan.csv`
* **Logic**: Apply **guardrails & trust policy**:

  * If `|price_change| > 20%` → **manual review**
  * If `inventory < 10` → **reject**
  * If `labor_cost > $200/store/day` → **manual review/reject**
    Else → **auto-approve**
* **Output**: `finalized_actions.csv` → `sku_id, action_type, decision (auto/man/reject), reason`
* **PDF tie-ins**: dynamic governance, guardrails examples & logging/audit. 

> Optional (from the PDF): **ProductAgent** as a “SKU digital twin” that accepts/filters proposals (state-aware), and **ScenarioScoutAgent** to discover overlooked SKUs. You don’t need them for your six-agent demo, but the design anticipates adding them later.

**PricingAgent** (`agents/pricing.py`)

```python
import json, pandas as pd, math
from settings import PRICING, BASELINE_PRICE_FILE, MAX_PRICE_CHANGE
from tools.data_tools import price_optimizer, write_csv

def run_pricing():
    po = pd.read_json(price_optimizer())              # sku_id, optimal_price, elasticity
    try:
        base = pd.read_csv(BASELINE_PRICE_FILE)       # sku_id, current_price
        df = po.merge(base, on="sku_id", how="left")
    except FileNotFoundError:
        df = po.copy()
        df["current_price"] = df["optimal_price"]     # fallback

    # propose price within guardrail if needed
    def propose(row):
        target = row["optimal_price"]
        cp = row["current_price"]
        delta = (target - cp) / cp if cp else 0.0
        if abs(delta) > MAX_PRICE_CHANGE:
            # cap to guardrail, note for governance to ask manual
            target = cp * (1 + math.copysign(MAX_PRICE_CHANGE, delta))
        return target

    df["proposed_price"] = df.apply(propose, axis=1)
    df["delta_pct"] = (df["proposed_price"] - df["current_price"]) / df["current_price"]
    # rough lift: elasticity * % change (toy model)
    df["expected_lift_units"] = (df["delta_pct"] * df["elasticity"]).abs() * 100
    out = df[["sku_id","current_price","proposed_price","delta_pct","expected_lift_units"]]
    write_csv(out, PRICING)
```

```python
from tools.data_tools import labor_simulator, write_csv
```

**FinanceAgent** (`agents/finance.py`)

```python
import pandas as pd
from settings import PRICING, CAMPAIGN, LABOR, RANKED
from tools.data_tools import write_csv

ASSUMED_UNIT_PRICE = 10.0  # replace with baseline_prices if available

def run_finance():
    p = pd.read_csv(PRICING)[["sku_id","expected_lift_units","proposed_price"]]
    m = pd.read_csv(CAMPAIGN)[["sku_id","total_spend","expected_lift_units"]]
    l = pd.read_csv(LABOR)[["sku_id","cost"]]

    df = p.merge(m, on="sku_id", suffixes=("_price","_mkt"), how="outer")
    df["expected_lift_units"] = df[["expected_lift_units_price","expected_lift_units_mkt"]].max(axis=1, skipna=True)
    df = df.merge(l, on="sku_id", how="left")

    price_for_rev = df["proposed_price"].fillna(ASSUMED_UNIT_PRICE)
    incr_revenue = df["expected_lift_units"].fillna(0) * price_for_rev
    costs = df["total_spend"].fillna(0) + df["cost"].fillna(0)

    df["roi"] = incr_revenue - costs
    df = df.sort_values("roi", ascending=False)
    df["rank"] = range(1, len(df)+1)
    out = df[["sku_id","roi","rank"]].copy()
    out["rationale"] = "Max net ROI given spend & labor"
    write_csv(out, RANKED)
```

```python
import pandas as pd
from settings import RANKED, FINAL, MIN_INVENTORY, MAX_PRICE_CHANGE, LABOR_COST_CAP
from tools.data_tools import get_inventory, write_csv
import json

def run_governance():
    ranked = pd.read_csv(RANKED)
    inv = pd.read_json(get_inventory())   # sku_id, inventory, lead_time

    # join aux data if available
    # you could also look back at pricing/labor to check exact deltas/costs
    df = ranked.merge(inv, on="sku_id", how="left")

    decisions = []
    for _, r in df.iterrows():
        decision, reason = "auto-approved", "Within guardrails"

        # inventory guardrail
        if r.get("inventory", 9999) < MIN_INVENTORY:
            decision, reason = "rejected", f"Inventory < {MIN_INVENTORY}"

        # labor guardrail (if you need exact cost, merge LABOR here)
        # price delta guardrail (merge PRICING for delta)
        # demo: if lead_time is long, force manual
        if decision == "auto-approved" and r.get("lead_time", 0) > 14:
            decision, reason = "manual review", "Long lead time"

        decisions.append({"sku_id": r.sku_id, "action_type":"price+campaign",
                          "decision": decision, "reason": reason})

    out = pd.DataFrame(decisions)
    write_csv(out, FINAL)
```

### Crew wires it together (`crew.py`)

```python
from crewai import Agent, Task, Crew
from tools import data_tools
from agents.trigger import run_trigger
from agents.pricing import run_pricing
from agents.marketing import run_marketing
from agents.labor import run_labor
from agents.finance import run_finance
from agents.governance import run_governance

# Agents (LLM-enabled for summaries), but tasks call deterministic functions.
trigger = Agent(role="TriggerAgent", goal="Detect underperformers and emit choice sets",
                backstory="Watches sales vs forecast daily and flags SKUs.")
pricing = Agent(role="PricingAgent", goal="Propose price actions using elasticity",
                backstory="Balances lift and margin, respects guardrails.")
marketing = Agent(role="MarketingAgent", goal="Recommend channel mix within budget",
                backstory="Allocates spend to maximize lift without saturation.")
labor = Agent(role="LaborAgent", goal="Estimate labor & ops load", backstory="Protects stores.")
finance = Agent(role="FinanceAgent", goal="Rank scenarios by ROI", backstory="Mini-P&L mind.")
governance = Agent(role="GovernanceAgent", goal="Apply guardrails and approvals",
                   backstory="Ensures safe, auditable actions.")

t1 = Task(description="Flag underperformers and write flagged_skus.csv & choice_sets.json",
          agent=trigger, expected_output="flagged_skus.csv, choice_sets.json",
          func=run_trigger)

t2 = Task(description="Generate price_scenarios.csv", agent=pricing,
          expected_output="price_scenarios.csv", func=run_pricing)

t3 = Task(description="Generate campaign_scenarios.csv", agent=marketing,
          expected_output="campaign_scenarios.csv", func=run_marketing)

t4 = Task(description="Generate labor_cost_estimates.csv", agent=labor,
          expected_output="labor_cost_estimates.csv", func=run_labor)

t5 = Task(description="Generate ranked_action_plan.csv", agent=finance,
          expected_output="ranked_action_plan.csv", func=run_finance)

t6 = Task(description="Generate finalized_actions.csv", agent=governance,
          expected_output="finalized_actions.csv", func=run_governance)

crew = Crew(agents=[trigger, pricing, marketing, labor, finance, governance],
            tasks=[t1, t2, t3, t4, t5, t6])
```

You’re seeing the `OPENAI_API_KEY is required` error because **CrewAI always tries to spin up an LLM for each Agent at init time**—even if your task logic is 100% deterministic (callbacks only). It’s how CrewAI is designed: “agents” are LLM-driven by default; role/goal/backstory + task description become part of a prompt. If no provider is configured, it complains about a missing key. ([docs.crewai.com][1])

Good news: you can still run your deterministic pipeline. Here’s the simplest way to think about it and fix it.

---

# What CrewAI uses the LLM for (plain English)

* **Agent fields**

  * **role / goal / backstory** → context text the LLM reads to “think like that agent.” ([docs.crewai.com][2])
* **Task fields**

  * **description / expected_output / tools / context** → instructions and constraints the LLM uses to produce an answer or decide tool calls. ([docs.crewai.com][3])
  * **callback** → your Python function that runs **after** the task completes (often after an LLM step) and gets the TaskOutput. It’s great for deterministic post-processing, file writes, etc. ([GitHub][4])

In your code you’re using callbacks (e.g., `run_trigger`) to do the real work. That can make the LLM step unnecessary—but **the library still tries to initialize an LLM object** by default, which is why your logs show the API key error. ([CrewAI][5])

---

# Two practical ways to run “deterministic agents”

## Option 1 — Keep CrewAI, but point it at a cheap/local provider (or a dummy key)

* If you’re not actually calling the LLM (because your tasks run via callbacks), you just need to **satisfy the init requirement**.

### Easiest quick fix

Set a dummy OpenAI key so the import-time check passes:

```bash
# .env or shell
OPENAI_API_KEY=dummy
```

This silences the “missing key” error in many setups. If you *accidentally* trigger a real LLM call, you’ll get a 401 later—so only do this if you truly don’t call the LLM. (Community tip.) ([CrewAI][5])

### Cleaner fix: give each Agent an explicit non-OpenAI LLM

If you have **Ollama** locally, tell CrewAI to use it:

```python
from crewai import LLM, Agent

local_llm = LLM(
    model="ollama/llama3.1",      # provider/model id
    base_url="http://localhost:11434",  # Ollama endpoint
    api_key="dummy",              # not used by Ollama, but satisfies checks
    temperature=0
)

def create_trigger_agent():
    return Agent(
        role="Trigger Agent",
        goal="Detect underperforming SKUs and flag them for action",
        backstory="You analyze sales vs forecast.",
        verbose=True,
        allow_delegation=False,
        llm=local_llm,            # 👈 prevents default OpenAI lookup
    )
```

CrewAI’s `LLM` class is meant for this: you pass provider/model config directly to agents instead of using the default. ([GitHub][6])

> If you *do* want an LLM sometimes (e.g., natural-language summaries later), this option is ideal: keep the agents intact and you can turn LLM use on per task as needed.

# What happens during `crew.kickoff()` (two modes)

**A) Typical (LLM) mode**

1. Crew builds a prompt from Agent (role/goal/backstory) + Task (description/expected_output/tools/context).
2. Sends to the configured LLM; the model may select tools, reason, and produce an answer.
3. Task `callback(output)` fires with the TaskOutput so you can save files, trigger side effects, etc. ([DeepWiki][8])

**B) Your “deterministic callback” style**

* You still create Agents/Tasks, but for each Task you rely on the **callback** to do the work (read CSVs, compute, write files).
* To avoid the crash during agent init, you must provide **some** LLM config (dummy/local/real). Even if it’s never called, the object must exist. ([CrewAI][5])

Given your code:

* **Trigger Agent / Task** → `run_trigger(threshold)`
  Reads sales, computes `gap_pct`, filters underperformers, writes `flagged_skus.csv` and `choice_sets.json`. (All deterministic.)

## Quick FAQ

**Q: Why do I need an LLM if my agents don’t use it?**
A: Because CrewAI’s **Agent** class is designed around LLMs. The framework wires agents → prompts → tool use. Even if your work is in callbacks, the Agent object still gets created and expects an LLM provider. (You can stub it.) ([docs.crewai.com][1])

**Q: Do role/goal/backstory matter if I don’t use the LLM?**
A: Not really—they’re only used to build prompts for the LLM. With callback-only tasks, they’re just metadata. ([docs.crewai.com][2])

**Q: Can a task run *only* the callback and skip the LLM step?**
A: In practice, yes—by supplying a no-op/unused LLM so init passes and doing all the work in the callback (like you’re doing). Some folks also run plain Python orchestration for truly LLM-free flows. ([GitHub][4])
